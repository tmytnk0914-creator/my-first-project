# レポート下書きSkill

## 手順

1. 次の3点を確認する。不足があれば**1回だけまとめて質問**し、回答がなければ「(要記入)」と明示した仮置きで進める:
   - 種類: 週次/月次レポート、企画書、報告書のどれか
   - 材料: 実績データ、メモ、参考資料(ファイルがあれば読む)
   - 読み手: 上司/チーム/社外 のどれか
2. 種類に応じて以下の構成で Markdown の初稿を作成する。

### レポート(週次・月次)の構成
```
# ○○レポート(期間)
## サマリー(3行以内。結論から)
## 主要数値(表。前期間との比較を必ず入れる)
## 良かった点(データの根拠つきで2〜3個)
## 課題・懸念(データの根拠つきで2〜3個)
## 次のアクション(担当と期限の欄を作る)
```

### 企画書の構成
```
# 企画名
## 背景・課題(なぜ今やるのか)
## 提案内容(何をやるのか。1文で言い切ってから詳細)
## 期待効果(数値目標。仮でも数字を置く)
## スケジュール(表)
## 必要リソース・コスト
## リスクと対策
```

3. 作成後、必ず以下を行う:
   - データから読み取った解釈には「(推測)」を付け、事実と区別する
   - 数値は材料にあるものだけを使い、**絶対に数値を創作しない**。不明な数値は「(要記入)」とする
   - 最後に「これは初稿です。特に◯◯の数値と△△の判断は確認してください」と要確認箇所を列挙する
4. `templates/提出前チェックリスト.md` を提示し、提出前の確認を促す。

## 絶対に守るルール

- 数値・固有名詞・実績の捏造は厳禁。材料にないものは「(要記入)」。
- 社外向け資料の場合は、トーンをフォーマルにし、最終確認が必須であることを強調する。
- 出力は必ず上記構成に従う(毎回形式がぶれないこと自体が価値)。
